# velo — React + Park UI rework (design)

Requested by Matteo: rebuild velo's UI in React with Park UI, following the redesign in `design/park-ui/` (README + reference mocks + Panda files). It's a visual and UX refresh: **behaviour stays the same** except for four small additions he approved (§5). He asked for it to be built on a branch and switched over in one go, with a spike first (done, §2). He was away while this was written, so calls marked **(my call)** are mine; everything else is his decision or comes from the design handoff.

## 1. Intent, goals, non-goals

- **Intent:** a polished, consistent, accessible UI he can keep customising with a real component library (Park UI = Ark UI + Panda CSS), without losing what makes velo good: speed, keyboard flow, no lost text.
- **Goals:**
  - Every screen and state in `design/park-ui/README.md` and `reference/*.dc.html`, light and dark, both layouts.
  - Behaviour parity with velo 0.3.0 (§4 checklist).
  - Four additions (§5).
- **Non-goals:**
  - Changes to the Rust backend beyond the note count (§5.1) and the "cleared shortcut" handling (§5.3).
  - Native right-click menus redesigned.
  - Rendering tables, alerts or footnotes inside Rich edit.
  - New features beyond §5.
- **Anti-goals (failure even if it works):**
  - Any path that loses typed text. The invariants in §4 must survive the port verbatim.
  - Search or typing that feels slower than 0.3.0. Per-keystroke search stays under 50 ms p95 at 10k notes; the list stays virtualised.
  - Keyboard flow regressions: every action still reachable without the mouse.
  - Locked-note plaintext persisted anywhere new: no localStorage, no React devtools persistence, no logs.

## 2. Spike results (branch `spike/park-react`, worktree `../velo-spike`, throwaway)

- **Works in WebKit with no runtime errors:** React 19.3 + `@ark-ui/react` 5.39 + Park UI v1 (CLI-generated components and recipes) + Panda **1.12.1**. Checked: dialog, tabs, menu, tooltip, segment group, Indigo/Slate tokens, velo semantic tokens, dark/light via `data-theme`, and CodeMirror 6 mounted inside a React component with the existing `writingSetup` and `richMarkdown`.
- **Panda 2.x is incompatible** with Park UI v1 components: they import `createStyleContext` from `styled-system/jsx` and `RecipeConfig` from `@pandacss/dev`, which Panda 2 renamed. **Pin `@pandacss/dev`, `preset-base` and `preset-panda` to 1.12.1.**
- **Park UI CLI (`@park-ui/cli` 1.0.1) quirks** and their fixes:
  - `init` needs a TTY (interactive prompts): drive it through a pty.
  - It needs `compilerOptions.baseUrl`, which TypeScript 6 deprecates: add `"ignoreDeprecations": "6.0"`.
  - It wrote every recipe, slot recipes included, into `recipes`: regenerate `src/theme/recipes/index.ts` by checking which files call `defineSlotRecipe`.
  - Its `@/theme/...` imports in `panda.config.ts` don't resolve in Panda's config bundler: use `./src/theme/...`.
  - The checkbox slot recipe emits one harmless codegen warning on Panda 1.12. Fix it if it shows visually.
- **macOS overlay title bar:** `titleBarStyle: "Overlay"` + `hiddenTitle` + `trafficLightPosition {16, 24}` compiles and the app launches. It was **not visually verified** (the screen was locked), so this is an owner check. A header drag region (`data-tauri-drag-region`) needs the `core:window:allow-start-dragging` permission.

## 3. How it gets made

### Stack (decided)
- React 19.3 + react-dom; `@ark-ui/react` 5.39; Park UI v1 components copied into `src/components/ui/` and recipes into `src/theme/` by the CLI; Panda CSS 1.12.1 with PostCSS (`postcss.config.cjs`), output in `styled-system/` (gitignored, generated by `panda codegen` before build, typecheck and test); `lucide-react` icons; `@vitejs/plugin-react`.
- Fonts bundled, never fetched (it's an offline desktop app): `@fontsource-variable/inter` and `@fontsource-variable/jetbrains-mono` 5.3.0.
- Park UI palette: accent **Indigo**, gray **Slate**, radii `l1` = 4 px, `l2` = 6 px, `l3` = 8 px.
- `velo.*` semantic tokens, font tokens, sizes, shadows and custom recipes ported from `design/park-ui/panda/*` to Park UI v1 / Panda 1.12 (`defineSemanticTokens`, `_light`/`_dark`).
  - Recipes: `listRow`, `searchMatch`, `tagChip`, `inlineTag`, `keyCap`, `segmented` (or Park's `segmentGroup` with velo variants, **my call**: prefer Park's component), `titleBar`, `divider`, `banner`, `previewPill`.
  - Exact values come from `reference/velo-park.css`.
- **Conditions:** `dark: '[data-theme=dark] &'`, `light: ':root &, [data-theme=light] &'`. The app always writes `data-theme`: Settings → Theme = System resolves through `matchMedia('(prefers-color-scheme: dark)')` and updates on its `change` event. The native window theme (`setTheme`) follows as in 0.3.0.

### Architecture (my call)
- **Keep the imperative logic modules unchanged**, since they hold the hard-won invariants: `saver.ts`, `history.ts`, `search.ts` (`enterAction`), `tags.ts`, `shortcuts.ts`, `contextmenu.ts`, `close.ts`, `latest.ts`, `errtext.ts`, `passphrase.ts` helpers, `settingsform.ts` pure helpers, `preview.ts` (`renderMarkdown` etc.), `richmd.ts`, `editortheme.ts` (restyled only), `divider.ts` (`clampSize`), and `list.ts`'s `visibleRange` and `Results` paging. Existing unit tests keep passing.
- **Port `main.ts` into an app controller** (`src/app/controller.ts`): the same functions and sequencing (`show`, `select`, `enter`, `deleteNote`, `lockHandoff`, `navigate`, `runSearch`, …) with the same `busy` / `latest()` / flush-then-load guards. Instead of touching the DOM, it writes to a small **observable store** (`src/app/store.ts`) that React reads through `useSyncExternalStore`. React components render that state and call controller actions; they never reimplement sequencing.
  - **Why:** the safest port of async ordering that has already been reviewed twice. Moving it into effects and hooks would rebuild it from scratch.
- **CodeMirror** is mounted once by an `<Editor>` component through a ref. `mountEditor`'s `Editor` interface stays the controller's handle.
- **Virtual list:** keep velo's fixed-height virtualisation (no new dependency), as a React component: `role="listbox"`, `role="option"` rows with a roving tabindex, row height from `fontScale` (§3.4).
- **Testable controller (my call):** `controller.ts` never touches the DOM. Everything UI-side (focus search/editor/list row, confirm/ask dialogs, passphrase prompt, rename field, opening the native menu, window calls) goes through an injected `UiPort` interface; the backend goes through the existing `api` module, injected so tests can mock it. Node vitest tests drive the riskiest sequences with fakes: Enter waiting for the pending search, refused switches while unsaved, the lock hand-off `busy` guard, delete then neighbour highlight, history navigation over a vanished note, and tag-prune highlighting without opening. **No new test dependencies.** Visual and interaction checks run in WebKit through a Playwright script with a Tauri IPC stub, kept outside the repo (scratchpad), and the §4 checklist is the owner's final pass.
- **Global keydown capture handler** stays a single window listener (capture phase) in the controller, reading the live bindings. Dialogs own their keys as today.
- **Native context menu** code (`openContextMenu`, `menuModel`) unchanged.

### Font scale
- Use `design/park-ui/panda/font-scale.ts` as is: editor `s + 2` with line height 1.7, compact row (vertical layout) `round(2.15·s)`, two-line row (horizontal layout) `round(3.3·s)`, title `round(17·s/14)`.
- The header stays at 13 px.
- Replaces the `--row-h` formula.

### Desktop specifics
- **macOS:** overlay title bar (config above). The header is the drag region, with 80 px left padding for the traffic lights, macOS only, detected by platform. Controls inside the header are not drag regions: Tauri ignores clicks on interactive elements; verify.
- **Windows/Linux:** native decorations, so no left padding.
- **Small window:** header breakpoints at ≥ 900 / 720–899 / < 720 px (README table), from a ResizeObserver on the header. The window minimum size is set in `tauri.conf.json` to **600×400 (my call)**.

## 4. Behaviour parity checklist (must hold after the switch)

Everything velo 0.3.0 does keeps working the same way:
- **Search and keyboard:**
  - Search-or-create: Enter opens the highlighted row, otherwise an exact title, otherwise creates; Shift+Enter creates; Enter waits for the pending search.
  - ↑/↓ move the selection without recording history; Esc clears; ⌘L focuses search.
- **Saving:**
  - Autosave; conflict copies plus the banner.
  - Flush-then-load on every switch, refused while unsaved; a `busy` guard around the lock hand-off.
  - The close flow asks about unsaved edits; blur flushes; indexing makes the editor read-only and the search box disabled, with progress in the title bar.
- **History:** ⌘J back / ⌘K forward over explicit visits, with auto-shown notes recorded on their first edit.
- **Lists and filtering:**
  - Sort Recent / A→Z (title matches first).
  - Paged list with a "Loading…" row.
  - Tag panel and filter (AND); the filter line; tags refreshed after saves, lock, rename and watcher events; selection pruning.
- **Editor modes:** preview toggle (⌘⇧P) with auto-edit for new or empty notes; Rich / Plain (⌘⇧R); clickable checkboxes in Rich and in Preview; footnote jumps; wikilinks, tags and links clickable (⌘-click in the editor).
- **Note actions:**
  - Rename: double-click or ⌘R, inline, with the rewrite-links confirmation.
  - Lock / unlock (⌘⇧E) and Lock all (⌥⌘E), passphrase setup.
  - Move to Trash with confirmation (⌘⌫ outside the editor and outside a non-empty search box).
- **Right-click and keyboard menu:** native context menu on rows (right-click, Shift+F10 / Menu key).
- **Settings:** folder, layout, theme, font size, sort, and remappable shortcuts (override-only storage, the legacy migration).
- **Layout and window:**
  - Draggable divider (title bar too in vertical layout); arrow keys nudge, double-click resets, size per layout.
  - ⌘⇧J toggles layout.
  - The global hotkey shows/hides velo and returns focus.
- **First run and recovery:** first-run folder chooser; the one-time index upgrade; external file changes picked up live.

## 5. Approved additions

1. **Note counts.**
   - The tag panel header ("Tags · 2 selected · 214 notes") and the filter line (count on the right) show how many notes the list would show for the current query + tag filter.
   - **Backend (my call):** `Page` gains `total: usize` from a `COUNT(*)` with the same WHERE clauses as `search_page`, computed only for the first page (offset 0) and reused for later pages. Unlocked locked notes are added from the in-memory set.
   - The perf test gets the count included; budget unchanged (< 50 ms p95).
2. **Search-match highlighting.**
   - Query terms are highlighted in titles and snippets (`searchMatch` recipe), case- and diacritic-insensitive like search, with the same `fold`.
   - Pure helper `highlightRanges(text, query): [start, end][]`: map folded positions back to original positions char by char, since NFD stripping changes lengths. Unit-tested on accents and multi-term queries.
3. **Clear a shortcut.**
   - In the shortcut recorder, ⌫ clears a binding, leaving the action without a key.
   - **Storage (my call):** the override value `"none"`. `resolve()` keeps `"none"` (no fallback to the default); matching never fires it; the label shows "—".
   - Rust: `toggle_window` = `"none"` registers no global hotkey.
   - The validator still checks conflicts only between real bindings.
4. **Retry on save error:** the title-bar error shows a Retry button (outline, sm) that calls `editor.flush()`.

## 6. Design adaptations to velo's real behaviour

- **Passphrase dialog (Matteo: "prioritize real behaviors").** velo keeps one X25519 identity in the OS keychain and only asks for the passphrase when it needs to create one (first lock ever) or to unlock `identity.age` (a new machine without the keychain entry). It never asks per note. So:
  - **Create** (first lock, or Lock all with no identity):
    - Title: "Create your velo passphrase".
    - Subtitle when triggered by a lock: "Needed once to lock “<note>”" (or "to lock all notes").
    - Warning: "It can't be recovered if you forget it."
    - Fields: passphrase + confirm; "Passphrases don't match"; buttons Cancel / Create & lock.
  - **Unlock** (identity exists only as `identity.age`):
    - Title: "Enter your velo passphrase".
    - Copy: "This computer doesn't have your velo key yet."
    - Error: "Wrong passphrase — try again" (`role=alert`); buttons Cancel / Unlock.
  - **No key anywhere (my call):** opening a locked note when there is neither a keychain entry nor `identity.age` used to open the create dialog, which makes a new key that can't decrypt the note. Instead, show no dialog: the title bar shows the error "This note was locked with a velo key that isn't on this computer. Copy `.velo/identity.age` from the other computer into this notes folder." Uses the existing `hasIdentity` / `identityFileExists` commands. Lock and Lock all still create the key as today.
  - Layout and styling follow the design (420 px, icon tile, one-line warning).
- **Conflict banner copy:** "This file changed on disk. Your edits were saved to <conflict note>", with a dismiss ×. It stays until dismissed or the note changes, as the design says (today it hides on note change only).
- **Preview cues:** pill, strip and watermark, as designed. Preview read-only = no caret (already true).
- **Overflow menu** (< 720 px): a Park `Menu` (Ark), not a hand-built popover, since React is available.
- **Settings:**
  - Tabs, a conflict state ("Already used by Forward", a red count badge on the tab, Save disabled with "1 conflict — fix it to save"), ⌘↩ saves.
  - Changed bindings get a blue dot; Reset is disabled at the default.
  - Today the recorder refuses conflicting keys outright. The design shows them as a conflict to resolve instead. Adopt the design: the draft may hold a conflict, and Save is blocked until it's fixed.
- **Search hints** in the field: `⌘L` when empty, `↩ Open` when a row is highlighted, `⇧↩ Create` when no title matches exactly, with live bindings.
- **List rows:** compact (one line) in vertical layout, two-line in horizontal; locked rows show a lock glyph + title, and the two-line snippet reads "Locked".
