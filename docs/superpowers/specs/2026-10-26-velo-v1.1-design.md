# velo v1.1 — design (fixes from first use + sort, history, remappable shortcuts)

Builds on v1 (`docs/superpowers/specs/2026-10-25-velo-design.md`, plan `docs/superpowers/plans/2026-10-25-velo-v1.md`). All v1 invariants still bind: no user text lost; locked-note plaintext never on disk/SQLite; files are source of truth; identity.age never overwritten.

## Why
Matteo used v1 on a 10k-note folder. Core flow works (per-keystroke filter, create on Enter, autosave, lock). The rough edges below break the keyboard-driven "summon, type, write, dismiss" loop that is the whole point of an nvALT successor.

## Fixes (bugs found in first use)

1. **No feedback while indexing.** Opening a 10k folder cold takes several seconds with no indication and a frozen window.
   - Indexing runs off the main thread; the window stays responsive.
   - A visible status line shows progress ("Indexing… 3,200 / 10,000"), disappearing when done.
   - **Matteo decided:** while indexing, search and editing are blocked (search field/editor disabled or showing the progress line; note commands return a "still indexing" state the UI shows). No writes run concurrently with the indexer. Window, settings and quit stay usable.
   - Applies to startup open, folder change, and passphrase-triggered reopen. Warm opens (index already up to date) should be near-instant and may skip the progress line.
2. **⌘R (rename) does nothing.** Find the cause (likely the webview's reload accelerator or the menu swallowing it) and fix so rename works from list, search field and editor.
3. **Lock all default shortcut.** Was ⌘⇧L; must not use L (⌘L is "focus search" muscle memory). New default **⌘⌥E** (my call; sits next to lock/unlock ⌘⇧E).
4. **Global hotkey hide leaves velo focused.** When the hotkey hides velo, focus must return to the previously active app (macOS: hide the application, not just the window — e.g. `AppHandle::hide()`; Windows/Linux: hide window, OS restores focus). Showing again brings velo front with the search field focused (existing `focus-search`).
5. **Enter doesn't focus the note.** After Enter opens or creates a note from the search field, the cursor goes to the editor text.
6. **Preview mode traps you.**
   - Creating a note (Enter or wikilink), or opening a note whose body is empty, automatically switches to edit mode.
   - Preview mode has a clear visible indicator (badge/toolbar state) whenever it is on.
   - An empty note shown in preview displays a watermark: "Empty note — press ⌘⇧P to edit" (uses the current toggle-preview binding).
7. **Wikilink to a missing note:** after creation, the new note is selected and visible in the list. Behavior: set the search field to the new title (nvALT-style, my call) so the list shows it selected; open in edit mode (fix 6).

## Features

### Sort mode
- Two modes: **Last modified** (current behavior, newest first) and **Title A→Z**.
- While searching, grouping stays: title matches first, then body matches; **within each group** sort by the chosen mode (Matteo decided).
- Empty query: whole list sorted by mode.
- Toggle: Settings + a remappable shortcut (default **⌘⇧S**, my call). Persisted in settings (`sort: "modified" | "title"`).
- A→Z compares folded titles (same `fold` as search: case/diacritic-insensitive).
- Ordering must be applied in the query, before any limit (not by re-sorting a capped page), so A→Z really returns the alphabetically first notes. Unlocked encrypted notes merged into results follow the same ordering.

### Full scrollable list (Matteo decided)
- The list is no longer capped at 200: with an empty query you can scroll through all notes (10k+), in either sort mode; with a query, all matches are reachable too.
- Approach (my call): results are fetched in pages (e.g. 200) as you scroll, with the list rendering only visible rows (virtualized) so 10k rows stay smooth. Keyboard navigation (↑/↓, next/prev note) loads further pages as needed.
- Budget: each page query <50 ms p95 at 10k notes in both sort modes; perf test covers first page and a deep page in both modes.

### Back / forward through visited notes
- Browser-like history of notes opened in the editor (by any means: list, Enter, wikilink, back/forward itself excluded from pushing).
- Back **⌘[**, Forward **⌘]** (defaults, remappable). Going back then opening a different note truncates the forward stack.
- Session only (Matteo decided); not persisted.
- Navigation uses the existing flush-then-load path (refused while unsaved — same as any switch). Entries whose file no longer exists are skipped. Renamed/locked notes: history entries follow the new path (update entries when rename/lock/unlock returns a new path).
- Consecutive duplicate entries collapse.

### All shortcuts remappable (Matteo decided: all of them, in Settings)
- Settings has a Shortcuts section listing every action with its current binding: focus search, next/prev note, toggle preview, rename, lock/unlock, lock all, settings, sort toggle, back, forward, and the global show/hide hotkey.
- Click a row, press the new combination to record it. Duplicate bindings are refused with a message naming the conflicting action. "Reset to defaults" per row and for all.
- Bindings persist in settings JSON (e.g. `shortcuts: { action: "Mod+Shift+P", … }`); unknown/missing entries fall back to defaults so old settings files keep working.
- The global hotkey moves into `shortcuts` (my call); an existing top-level `hotkey` value is migrated into it on load so a customised hotkey isn't lost. One string format ("Mod+…") in settings; converted to the plugin's "CommandOrControl+…" when registering.
- Match keys by physical key (`KeyboardEvent.code`) so Option-modified letters on macOS (dead keys) still match.
- `Mod` = ⌘ on macOS, Ctrl on Windows/Linux. Display uses platform symbols.
- In-app shortcuts are handled at window level before CodeMirror (existing capture-phase approach) so editor keymaps can't swallow them; the global hotkey keeps using tauri-plugin-global-shortcut (re-registered on change, old kept on failure — existing behavior).
- Fixed, non-remappable: Enter in search (open/create), Esc in editor (back to search), ↑/↓ in search/list, standard Edit menu (undo/redo/cut/copy/paste/select all), ⌘Q.

## Non-goals
- Persisted history, per-folder shortcut profiles, chorded/multi-key shortcuts, sort by created date or custom order.
- Fixing the v1 deferred-minor backlog (scratchpad ledger) except where touched.

## Anti-goals
- Any change that weakens v1 invariants (text loss, plaintext leaks).
- A shortcut recorder that can leave the app with no way to open Settings (Settings must stay reachable via the toolbar button even if its shortcut is unbound or broken).
- Search slower than the 50 ms p95 budget.

## Platforms
macOS first (my call). Windows and Linux must keep working: fix 4 there just hides the window; shortcuts use Ctrl for Mod.

## Left to the builder
Exact indicator/badge styling, progress-line placement, how progress is reported from Rust (events vs polling), the recorder UI details, internal data structures for history.
