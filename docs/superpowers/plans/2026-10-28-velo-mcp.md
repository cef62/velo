# Agent access (MCP server) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude Code can search, read, create, edit and manage velo notes through an MCP server. The server is velo's own binary run headless (`velo --mcp`), and it works whether velo is open or closed.

**Architecture:**
- **One set of tool handlers** (`agent/tools.rs`) runs against a `NoteOps` trait.
  - `DirectOps` wraps a `Vault`. The headless process uses it when velo is closed, and the app uses it for notes that aren't open in the editor.
  - `AppOps`, inside the running app, sends writes to the note open in the editor through the webview (event with a reply, 5 s timeout) and everything else to `DirectOps`.
- **Transport:** the headless process speaks MCP over stdio (`rmcp`). It either forwards each tool call (`{name, args}` plus a token) over loopback TCP to the running app, which runs the same handler, or runs it directly.

**Tech Stack:** Rust (Tauri 2, rusqlite, tokio), `rmcp` 3.x (stdio server) if acceptable, otherwise hand-written JSON-RPC; React 19 + CodeMirror 6 for the editor side; vitest, cargo test.

**Spec:** `docs/superpowers/specs/2026-10-28-velo-mcp-design.md`

## Global Constraints

- **Activation:** off by default. Setting `agent_access: bool`, default `false`. The headless process re-reads `settings.json` on every tool call.
- **Off message:** when access is off, every tool returns `Agent access is off — turn it on in velo Settings → General`.
- **Locked notes:** `*.md.age` are never listed, searched or returned, even while unlocked in the app. A tool naming one returns `not found`. Headless mode never reads the keychain or the identity, and never decrypts.
- **Deletes:** only to the OS Trash (existing `move_to_trash`). There is no permanent delete.
- **Overwrites:** `edit_note` requires `old_text` to occur exactly once. On 0 or ≥2 matches it fails with the count.
  - `replace_note` requires `expected_hash` = `store::hash` of the full on-disk bytes. A mismatch fails with `note changed since you read it`.
  - Every write tool returns the new `hash`.
- **One writer:** when velo is open and the note is open in the editor, writes go through the editor (`Editor.applyChange` / `appendLine`). With no answer within 5 s, the tool fails with `velo is busy, retry` and never writes directly.
- **Running-app detection:** `<app data>/agent.json`, mode 0600, holds `{ "port", "token" (32 random bytes, hex), "pid" }`. The listener binds to `127.0.0.1` only. The token is required on every request.
  - pid alive but the connection fails: retry for up to 2 s, then `velo is busy, retry`.
  - pid dead or no file: direct mode.
  - The app removes the file when access is turned off or on quit.
- **Undo trail:** every write tool requires `summary: string`. Before writing, the note is snapshot without the 10-minute throttle, and a sidecar `<ms>.json` `{ "summary", "agent": true }` sits next to the snapshot.
  - A created note gets a first revision of its created text, with its summary.
  - Snapshots in the same millisecond bump the later timestamp by 1 ms.
- **Limits:** bulk tools take ≤ 200 notes per call; more is rejected. Each note is its own write. Results are per note: `changed` | `unchanged` | `failed: <reason>`. Search returns ≤ 50 results per page.
- **Tags:** matched with velo's `fold`. `add_tags` writes the front-matter `tags:` list, or appends a `#tag` line when `write_front_matter` is off. It skips a note that already has the tag anywhere.
  - `remove_tags` removes the tag from `tags:` and removes exact inline `#tag` words (same rule as the tag extractor). Code and links are never touched.
- **Paths:** app data and config dirs are computed from the identifier `dev.velo.app` exactly as Tauri computes them.
- **Platforms:** macOS and Linux. On Windows `--mcp` prints "not supported yet" and exits 1.
- **Headless:** no window, no global shortcuts, no update checker, no Dock or tray, no focus stealing.
- **Workflow:** AGENTS.md / CONTRIBUTING.md: branch `feat/mcp`, quality gate, changeset (minor), PR with adversarial review.

## Review Focus

1. **Velo starts or quits mid-session.** A tool call made while velo is starting up (pid alive, listener not bound yet) must not write directly. Test in Task 7.
2. **Unlocked locked note.** A note encrypted on disk but unlocked in the running app never appears in `search_notes`, `list_tasks` or `list_tags` counts, and is not readable by title. Test in Task 2 (direct) and Task 6 (app).
3. **Stale reads.** `edit_note` after the note changed elsewhere (old text gone, or present twice) fails cleanly with no write. `replace_note` with a hash from before velo stamped front matter fails. Test in Task 2.
4. **Bulk partial failure.** `add_tags` over 3 notes where one disappears mid-call gives 2 `changed` and 1 `failed`, each changed note with its own agent revision. Test in Task 4.
5. **Toggle off mid-session.** After the user turns access off, the next call is refused in both modes, and `agent.json` is gone. Test in Task 6 (app side) and Task 1 (settings re-read).

### Task 6: Running app: listener, `agent.json`, `AppOps` with editor routing

**Files:**
- Create: `src-tauri/src/agent/listener.rs`, `src-tauri/src/agent/app_ops.rs`
- Modify: `src-tauri/src/commands.rs` (start or stop the listener on startup and in `set_settings`), `src-tauri/src/lib.rs`, `src/editor.ts` (`applyChange`), `src/app/controller.ts` (agent write handler), `src/ui/main.tsx` (listener), `src/app/fakes.ts`

**Interfaces:**
- Produces:
  - `listener::start(app: AppHandle) -> anyhow::Result<ListenerHandle>`:
    - binds `127.0.0.1:0`;
    - writes `agent.json` `{port, token, pid}` with mode 0600 (atomic write);
    - accepts newline-delimited JSON requests `{token, name, args}` and replies `{ok: Value} | {err: String}`;
    - a wrong token gets `{err:"unauthorized"}` and the connection is closed.
    - `ListenerHandle::stop()` closes the socket and deletes `agent.json`.
  - Started when `agent_access` is on (startup and `set_settings`); stopped when it's turned off and on app exit.
  - `AppOps` implements `NoteOps` over the app's `AppState` vault. It filters out encrypted notes even when they're unlocked in memory (Review Focus 2).
  - For `write` to a path open in the editor, it emits `agent-write` `{ id, path, kind: "replace"|"append", from?, to?, insert, summary }` to the webview and waits for the `agent_write_done(id, result)` command, up to 5 s. No reply gives `Err("velo is busy, retry")`.
  - `Editor.applyChange(change: { from: number; to: number; insert: string }): boolean`: a user edit, false when not editable.
  - The controller handler applies the change through the editor, flushes, and replies `{ hash }`, `refused` or `conflict`. It snapshots with the summary first via a `snapshot_agent` command.
- Ruling to apply: "is the note open?" is answered by the webview inside the same `agent-write` round trip (it replies `not-open`, and the backend then writes directly). There is no separate query.

### Task 7: Headless forwarding vs direct

**Files:** Modify `src-tauri/src/agent/mod.rs`; create `src-tauri/src/agent/client.rs`

**Interfaces:**
- Consumes: `agent.json` (Task 6), `DirectOps` (Task 2), `listener` protocol.
- Produces: `fn route(call) -> Result<Value, String>`, run per call:
  1. Re-read settings; when off, refuse.
  2. If `agent.json` exists and its pid is alive, connect and forward with the token, retrying for up to 2 s. Still failing gives `velo is busy, retry` and never direct.
  3. No file, or a dead pid: direct mode, with a lazily opened `DirectOps` that runs `open_with_progress` (warm reconcile) on first use and stays open for the session.
  4. Re-check per call, so velo starting or quitting mid-session switches modes.
- `fn pid_alive(pid: u32) -> bool` (`kill(pid, 0)` on Unix).
