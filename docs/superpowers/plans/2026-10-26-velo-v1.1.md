# velo v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the first-use rough edges of velo v1 and add sort modes, a full scrollable list, back/forward history and fully remappable shortcuts.

**Architecture:** Same Tauri 2 app. Rust: settings gain `sort` + `shortcuts`; the index search becomes paged and sort-aware in SQL; vault opening moves to a background thread with progress events and an "indexing" gate. TS: a pure `shortcuts.ts` drives one capture-phase key handler; the result list becomes a paged, virtualized component; history is a pure module; preview/enter/wikilink fixes live in `main.ts`/`preview.ts`.

**Tech Stack:** unchanged (Tauri 2, Rust, rusqlite FTS5, TypeScript + Vite + CodeMirror 6, vitest). No new dependencies unless stated.

**Spec:** `docs/superpowers/specs/2026-10-26-velo-v1.1-design.md` (v1 spec and plan still bind).

## Global Constraints

- v1 invariants hold: no user text lost; plaintext of locked notes never on disk or in SQLite; files are source of truth; index rebuildable; identity.age never overwritten; every note switch goes through the flush-then-load path that refuses while unsaved (`editor.flush()` → `editor.load()`), and navigation is refused while `busy` (lock hand-off).
- Search page query <50 ms p95 at 10k notes (release build), both sort modes, first page and deep pages.
- Old v1 `settings.json` files (top-level `hotkey`, no `sort`/`shortcuts`) must load; a customised hotkey is preserved.
- `Mod` = ⌘ on macOS, Ctrl on Windows/Linux. Keys matched by `KeyboardEvent.code`.
- Settings must stay reachable via the toolbar gear button regardless of bindings.
- Fixed (not remappable): Enter in search, Esc in editor, ↑/↓ in search/list, Edit menu (undo/redo/cut/copy/paste/select all), ⌘Q.
- macOS first; Windows/Linux must keep building and working.

## Binding format and defaults (used by Tasks 1, 4, 5)

A binding string is `+`-joined modifiers from `Mod`, `Ctrl`, `Alt`, `Shift` (in that order) followed by one `KeyboardEvent.code` value, e.g. `Mod+Shift+KeyP`, `Mod+BracketLeft`, `Mod+Comma`, `Mod+Shift+Space`. `Ctrl` means the physical Control key and is only meaningful on macOS (on Win/Linux `Mod` already is Ctrl).

| Action id | Default |
|---|---|
| `focus_search` | `Mod+KeyL` |
| `next_note` | `Mod+KeyJ` |
| `prev_note` | `Mod+KeyK` |
| `toggle_preview` | `Mod+Shift+KeyP` |
| `rename` | `Mod+KeyR` |
| `toggle_lock` | `Mod+Shift+KeyE` |
| `lock_all` | `Mod+Alt+KeyE` |
| `settings` | `Mod+Comma` |
| `toggle_sort` | `Mod+Shift+KeyS` |
| `back` | `Mod+BracketLeft` |
| `forward` | `Mod+BracketRight` |
| `toggle_window` (global) | `Mod+Shift+Space` |

Reserved (refused by the recorder): `Mod+KeyQ`, `Mod+KeyC`, `Mod+KeyV`, `Mod+KeyX`, `Mod+KeyZ`, `Mod+Shift+KeyZ`, `Mod+KeyA`. A binding must contain `Mod`, `Ctrl` or `Alt`, unless the key is `F1`–`F12`.

## Review Focus

1. A v1 settings file (`{"notes_dir": "...", "hotkey": "CommandOrControl+Alt+KeyN", "layout": "horizontal", "font_size": 16}`) → loads with `shortcuts.toggle_window == "Mod+Alt+KeyN"`, `sort == "modified"`, other fields kept. Pinned in Task 1 (`v1_settings_migrate`).
2. User records a plain letter, a reserved key, or a binding already used by another action → refused with a message naming the reason/conflicting action; nothing saved. Pinned in Task 4 (`validateBinding` tests).
3. `notes-changed` arrives while scrolled deep in the list → the list refreshes in place: scroll position kept, open note stays selected, no jump to top. Pinned in Task 6 (`refresh keeps window and selection`).
4. Back/forward onto a note deleted or renamed outside velo → deleted entries are skipped (no error loop); renamed-in-velo entries follow the new path. Pinned in Task 7.
5. Folder change (or quit) while a cold index is running → no panic; on failure the previous vault and watcher stay usable; the `indexing` gate is always cleared. Pinned in Task 3 (`indexing_gate_cleared_on_error`).

Ordering and paging (the part tests don't fully determine):
- Sort key: `Modified` → `mtime DESC, path ASC`; `Title` → `title_folded ASC, path ASC`. Add `CREATE INDEX IF NOT EXISTS notes_mtime ON notes(mtime)` and `notes_title ON notes(title_folded)`.
- Empty query: one `SELECT … ORDER BY <key> LIMIT limit+1 OFFSET offset`.
- Non-empty query: one SQL statement producing group 0 (title matches, existing LIKE conditions) `UNION ALL` group 1 (FTS matches per existing long/short-term rules, excluding rows that satisfy the title condition), `ORDER BY grp, <key> LIMIT limit+1 OFFSET offset`. Snippets computed only for returned rows (existing Rust snippet logic).
- Unlocked encrypted body matches (not in FTS) form group 2, appended after all SQL rows: sorted by the same key, served once offset passes the SQL rows (fetch SQL `limit+1`; if fewer SQL rows than requested, fill from group 2 at offset `offset - sql_total`, where `sql_total` is obtained with a `COUNT(*)` only when the SQL page came back short). (Planner's call: rare case, keeps the SQL path simple.)
- `has_more` = more rows exist beyond this page.
